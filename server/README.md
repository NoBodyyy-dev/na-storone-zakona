# Боты коллегии «На стороне Закона»

Два бота с идентичным функционалом: **Telegram** (на [grammY](https://grammy.dev)) и **MAX** (на официальной [`@maxhub/max-bot-api`](https://www.npmjs.com/package/@maxhub/max-bot-api)). Данные — в PostgreSQL, уведомления адвокатам — по почте.

## Запуск

```bash
npm install
cp .env.example .env      # вписать DATABASE_URL, токены, SMTP
npm run db:setup          # схема + справочник адвокатов и услуг
npm start
```

Токены: Telegram — у [@BotFather](https://t.me/BotFather), MAX — у `@MasterBot` внутри MAX.

Если задан только один токен, поднимется только этот бот. А вот без `DATABASE_URL` сервис не стартует: лучше упасть сразу, чем принимать записи и терять их.

## Что умеют боты

- **Приветствие** — официальное, от лица коллегии, с эмблемой и описанием возможностей.
- **Запись к адвокату** — четыре шага, всё кнопками: адвокат → услуга с ценой → день → время → подтверждение.
- **Уведомление адвокату** — при новой записи на почту Богданова С. В. или Богдановой И. Н. (в зависимости от того, к кому записались) уходит письмо с услугой, временем и контактом клиента.
- **Мои записи** — просмотр и отмена.
- **Контакты коллегии** — адрес, телефоны, реестровые номера.

Команды: `/start`, `/zapis`, `/my`, `/contacts`, `/menu`.

## База данных

```
advocates   id, имя, роль, специализация, реестр, телефон,
            email, telegram_id, max_id
services    услуги адвоката: название, цена, примечание
bookings    platform, user_id, advocate_id, service_id,
            slot_at, notified_at
```

### Как исключается двойная запись

Уникальным индексом:

```sql
CREATE UNIQUE INDEX bookings_slot_unique ON bookings (advocate_id, slot_at);
```

Приложение **не** проверяет занятость перед вставкой — любая такая проверка оставляет окно между «проверил» и «вставил». Вместо этого оно вставляет и ловит код `23505`. Гарантия живёт в БД, поэтому её не пробьёт ни гонка двух ботов, ни второй инстанс процесса, ни ручной `INSERT`.

Проверено тестом `concurrency.test.mjs`: 20 одновременных попыток занять один слот из обоих ботов — ровно одна побеждает, 19 получают отказ.

Занятые слоты при этом ещё и не показываются: список времени строится из `takenSlots()`, так что до конфликта дело доходит редко.

## Почта

`src/core/mailer.js`, nodemailer. Адрес берётся из `advocates.email` — не из конфига, поэтому смена почты адвоката делается в БД, а не в коде.

Отправка не блокирует ответ клиенту и не отменяет запись: если SMTP недоступен, клиент всё равно записан, а ошибка уходит в лог. Успешная отправка проставляет `bookings.notified_at`.

## Устройство

Логика сценария лежит в `src/core/flow.js` и не знает ни про Telegram, ни про MAX. Каждая её функция возвращает «экран»:

```js
{ text: '…', image: 'emblem', buttons: [[{ label: 'Записаться', data: 'book' }]] }
```

Адаптеры (`src/adapters/`) только переводят экран в вызовы своей платформы. Поэтому функционал ботов совпадает **по построению**: чтобы он разошёлся, нужно специально править оба адаптера.

```
src/
  index.js              БД → справочник → почта → боты
  db/
    schema.sql          таблицы и индексы
    pool.js             пул соединений, транзакции
    init.js             npm run db:init
    seed.js             npm run db:seed — адвокаты и услуги
    advocates.js        чтение справочника
    bookings.js         записи: занять, отменить, список
  core/
    flow.js             сценарий: экраны и маршрутизатор кнопок
    catalog.js          справочник в памяти (загружен из БД)
    schedule.js         рабочие дни и свободные слоты
    mailer.js           письма адвокатам
    assets.js           путь к эмблеме — берётся из client/
  data/collegium.js     реквизиты коллегии
  adapters/
    telegram.js         grammY
    max.js              @maxhub/max-bot-api
test/                   сценарий, гонка, лимиты клавиатур
```

Справочник адвокатов читается на каждое нажатие кнопки, но меняется раз в год — поэтому он загружается в память при старте (`catalog.js`), а в БД ходят только записи на приём.

## Расписание

Пн–пт 10:00–18:00, сб 10:00–14:00, вс — выходной. Слоты часовые, горизонт записи — 14 дней, запись не раньше чем за 2 часа до приёма. Настраивается в `src/core/schedule.js`.

Слоты трактуются в часовом поясе процесса — держите `TZ=Europe/Moscow`, иначе время в БД разойдётся с местным временем коллегии.

## Тесты

```bash
DATABASE_URL=postgres://... npm test
```

Нужна настоящая PostgreSQL — тесты проверяют constraint БД, на моках это бессмысленно. Для локального прогона:

```bash
docker run -d --name nsz-pg -e POSTGRES_PASSWORD=nsz -e POSTGRES_USER=nsz \
  -e POSTGRES_DB=nsz_bots -p 55432:5432 postgres:16-alpine
export DATABASE_URL=postgres://nsz:nsz@localhost:55432/nsz_bots
npm run db:setup && npm test
```

SMTP в тестах подменяется перехватчиком — наружу писем не уходит.

## Ограничения

- Черновик выбора живёт в памяти процесса: после перезапуска недожатая цепочка кнопок вернёт «начнём заново» вместо ошибки.
- Отмена записи адвокату по почте не сообщается — уведомление шлётся только при создании.
- `telegram_id` / `max_id` адвокатов в БД есть, но пока не используются: под них закладывалось дублирование уведомления в мессенджер.
